# Final Showcase Guide

## Purpose

Each shortlisted idea gets demoed by its group in front of the full workshop. This closes the loop from "art of the possible" → group ideation → working demo, and gives David James leadership a tangible, business-goal-linked view of what Copilot could do for them.

## Before the showcase

1. In the Idea Board app, review the **Shortlisted** column and confirm the running order (you can sort/group by topic using the topic filter).
2. Click **Print Showcase Cards** to generate one page per shortlisted idea, showing: group, topic, title, business goal, description, impact notes, demo plan, and presenter(s). Use these as cue cards, a running order handout, or a printed program for the room.
3. Confirm each group has their demo environment ready (Copilot Studio agent published/testable, M365 Copilot prompt or workflow ready to run, GitHub Copilot example ready to show, etc.).

## Suggested format per group (5–7 minutes)

1. **The problem** (30–60 sec) — what business goal / day-to-day pain does this address?
2. **The idea** (1 min) — what did you build and why?
3. **Live demo** (2–4 min) — show it working, even if it's a simplified test scenario.
4. **Impact** (30–60 sec) — time saved, risk reduced, or client experience improved — tie back explicitly to the business goal.
5. **Q&A** (1–2 min, optional) — facilitator moderates.

## Facilitator role during the showcase

- Keep time — use a visible timer if possible.
- After each demo, briefly restate the business goal link so leadership sees the thread from goal → idea → demo.
- Note any follow-up actions or owners for ideas that leadership wants to pursue further.

## After the showcase

- Export the full board (**Export JSON** + **Export CSV**) as the leave-behind artifact — it includes both shortlisted (demoed) and idea-only (backlog) items.
- Share the exported file and this doc set with David James leadership/IT as a record of the day and a prioritised backlog for follow-up pilots.
